Module 1 · 20 Min

Catching Version Drift Before Production

"I upgraded the model and my incident agent stopped behaving."
Why This Matters:

Same model family, new release: output format shifts, tool-call sequence reverses, verbosity or refusals spike. Teams find out from a broken incident channel or a confused on-call engineer. Here we implement an automated pre-flight eval gate.

Timing Breakdown (20 Min):

10 MinPair Eval Gate Run
2 MinGate Debrief
Support Material to Prepare:
  • Golden eval set: 10–15 alert payloads with expected tool sequences & pass/fail script.
  • Side-by-side diff notebook (Model v1 vs Model v2 highlighted diffs).
  • One-page model upgrade checklist: version pinning, eval gate, canary, rollback.

Module 4 · 25 Min

Precise Context Beats Big Context

"We dumped everything into context — and the agent hallucinated."
Why This Matters:

Dumping entire dashboards, raw stdout, and giant runbooks into context feels safe. In production, it increases token costs 10x, inflates latency by 4s, and causes models to lose the needle in the haystack. We contrast 3 context bundles against a planted ground truth.

The 3 Context Bundles Tested:
80k TokensRaw stdout dump
8k TokensRegex/filtered logs
2k TokensStructured JSON event
Planted Ground Truth Trap:

Bundle contains 1 decoy error from 3 days ago. Does the 80k raw context agent blame the old decoy instead of the active payments pool freeze?

Module 5 · 25 Min

Blast Radius via Knowledge Graphs

"A DB node just died — what else is on fire?"
Why This Matters:

When an agent must discover topology at runtime, it executes 5 sequential tool queries (K8s services, AWS RDS, ingress, DNS), burning 30s and frequently giving incomplete blast radius assessments. A Knowledge Graph answers "what downstream services will fail" in 1 deterministic hop.

The Architectural Contrast:
Lookup-on-the-Fly5 tool calls · 18.4s · Fragile
Graph-Backed1 query · 0.24s · Deterministic
Graph Dataset (25 Nodes):

Services (payments, checkout, cart), Databases (postgres-primary), Queues (kafka-orders), SLOs, and team ownership mappings.

Module 6 · 25 Min

The 50-Tool Ceiling & Routing Past It

"At 5 tools the agent is sharp. At 50 it picks the wrong one."
Why This Matters:

Every JSON tool schema injected into the system prompt costs tokens (~80–120 tokens per tool) and dilutes selection focus. At 60 tools, schemas consume 5,000+ tokens on every turn and accuracy drops from 95% down to 64%. We measure the threshold and wire a dynamic tool router.

The Scaling Dropoff Curve:
5 Tools96% Accuracy · 420 Tok
20 Tools88% Accuracy · 1,680 Tok
60 Tools64% Accuracy · 5,040 Tok
The Fix: 2-Stage Semantic Router:

Embedding or category-based tool router filters the 60 tools down to the 4 most relevant before calling the primary LLM planner.

cd agent && python3 mini_agent.py (Deprive / Comment tools in config.yaml)
Module 7 · 30 Min

SRE Skills & Description Engineering

"We wrote a Kafka skill and the agent never uses it."
Why This Matters:

A skill packages reusable on-call expertise: instructions, triage scripts, and when-to-use conditions. If the description is vague, the agent never dispatches it; if ambiguous, it triggers at the wrong time. The description IS the routing layer. Pairs write a skill and test it against peers' agents.

Timing Breakdown (30 Min):

12 MinWrite Skill
7 MinSwap & Test
3 MinDebrief
Anatomy of a Production SRE Skill:

YAML Frontmatter (name, trigger description, required tools) + Step-by-step triage sequence + Mitigation verification command.

Module 8 · 35 Min

Choosing the Right Memory Layer

"Working memory, session state, or vector store — and at what cost?"
Why This Matters:

Working memory (context window), session memory (this active incident), long-term memory (past postmortems), and shared organizational memory each trade off cost, staleness, and retrieval quality. Pairs map the tiers to our running payments scenario and size the cost using the interactive calculator.

The 3 Incident Agent Archetypes Sized:
1. Quick Triage Bot3-turn run · Ephemeral
2. Incident Lead45-turn war-room state
3. Postmortem SearchOrg-wide RAG store
Key Takeaway for Leadership:

Never use raw RAG for live operational state. Use fast session state stores (Redis) during the incident; serialize to vector embeddings only for post-incident search.
